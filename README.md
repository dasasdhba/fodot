# Fodot

I'm trying some werid patterns to make `F#` work with Godot. As for now, we can actually use most of C# bindings, except that gd virtual function will not work at all. Some common choices are using `C#` as a bridge and one can make source generator to do that. But I'm trying some other approaches. To write logic with `F#`, I "bind" a custom `F#` class with the node, by setting node's group, metadata, or method calls, and attaching specific attribute data with `F#` scripting class, so that they can be binded together. To tracking node's process, I simply used `SceneTree.process_frame`, which may cause performance issue, as for most case we need to make sure the process order is correct, but for now I don't find any effective way to do that. If you don't even care, you may directly make it unordered, and it should be even faster than `gdscript`. Generally, if you do need to make use of some gd virtual calls, bridges are unavoidable. I think the ideal way is using `F#` to write logic while using `gdscript` to do rendering and other stuff, so that you don't really need too many gd virtual calls.

However, writing glue code with node's exported value can still be very annoying, so I made a source generator that reads yaml config file and generates both `gdscript` and `F#` bindings. (Due to [existing issue](https://github.com/godotengine/godot/issues/105299) of Godot, we cannot directly import yaml as gdscript, so I made this alternate option, though you can find importer version in previous commit.) I'm not sure whether this can work well, it's just a proof of concept.

I'm probably going to work on some more general game system based on this, to see whether this concept can be useful. BTW this project is using `.NET 10.0` just for experiments, as I found this can make compiling faster.
